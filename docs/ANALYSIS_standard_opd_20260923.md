# 传统逐 Token OPD 实验分析：口径、过程、实现审计与文献对照

对象：`omniopd_runs/opd_standard_20260923_18`（86 步、八卡、LoRA rank16、LR 1e-6、1 epoch）
及其 140 局配对评测。

## 一、分析一次 OPD 该看什么（口径与判读规则）

分三层，**必须按顺序看**，因为下层的失败会让上层毫无信息量：

**第 1 层：优化层（训练是否真的在动）**

| 指标 | 来源 | 判读 |
|---|---|---|
| `actor/distillation/loss` 趋势 | train.log | 固定状态池上应随步数下降；**平 = 没学到** |
| `actor/grad_norm` | train.log | 量级 10–100 正常；≈0 说明梯度断了（对照 O23 的假通过） |
| `actor/entropy` | train.log | 降到 0 附近 = 分布塌缩；匹配 teacher 应趋近 teacher 的熵而不是 0 |
| `response_length/mean` | train.log | 大幅缩短往往伴随"放弃式"行为 |
| **权重更新幅度** `‖ΔW‖_F/‖W‖_F` | `scripts/diagnose_adapter_scale.py` | **最关键**：< 1e-4 时行为不可能变，不必去评 140 局 |

**第 2 层：行为层（模型到底变没变）**

| 指标 | 来源 | 判读 |
|---|---|---|
| adapter 对 logits 的影响 | `scripts/merge_adapter_for_serving.py` | 与评测/导出噪声比较；影响 ≤ 噪声则结果不可解释 |
| 同状态 greedy 动作改变率 | 需要固定状态集上跑 base 与 adapter | 直接量化"行为变了多少" |
| invalid 动作率、平均步数 | 评测 JSON 的 summary | 便宜的辅助轴，比胜率更快看到变化 |

**第 3 层：结果层（有没有用）**

| 指标 | 来源 | 判读 |
|---|---|---|
| 同批配对的胜负局数（非两个独立比例） | 两个评测 JSON 的 `episodes` 按 `game_id` 对齐 | 用 McNemar；必须同环境种子 |
| **同配置复测漂移** | 冻结基线重复测一次 | 这是噪声尺度；效应小于它就不可采信 |
| 分任务族明细 | summary.by_task_type | 方向不一致时不要只看总数 |

判停规则（本次总结出来的）：第 1 层的更新幅度不达标时，先调优化/目标，不要先扩评测——
否则是在用大样本去测一个没有信号的系统。

## 二、本次实验的过程分析（真实数据）

### 优化层

| 指标 | 前 10 步均值 | 后 10 步均值 | 斜率/步 | 全程范围 |
|---|---|---|---|---|
| distillation/loss | 6.37 | 7.14 | **+0.0081** | 2.31 – 13.68 |
| grad_norm | 40.8 | 46.3 | +0.087 | 7.51 – 128.1 |
| entropy | 0.457 | 0.188 | **−0.0024** | 0.017 – 1.362 |
| response_length/mean | 77.1 | 58.1 | −0.18 | 7.6 – 177.2 |

读法：损失**没有下降**（反而 +11%，且在步间噪声范围内），而熵掉了 **85%**。
这不是"在向 teacher 收敛"的形态，而是"在自己采样的 token 上做交叉熵、顺带把分布变尖"的形态
（见第三层 B 项）。

权重更新幅度（`diagnose_adapter_scale.py`，对 252 个模块求 Frobenius 总比）：

| adapter | 相对权重变化 |
|---|---|
| 第 43 步 | 4.12e-5 |
| 第 86 步 | 7.78e-5 |

线性增长 ≈ 9e-7/步。要到达 1e-3（行为可能变化的量级）需要约 **1100 步**，
到达 1e-2 需要约 **11000 步**；本次只有 86 步。

### 行为层

| 指标 | OPD | 冻结 base |
|---|---|---|
| adapter 对真实状态提示词 logits 的最大影响 | 0.326 | — |
| bf16 导出合并误差（同提示词） | 0.490 | — |
| 评测 invalid 回合总数 | 452 | 421 |
| 评测总步数 | 3233 | 3208 |

读法：连"无效动作数"这种粗粒度行为轴都几乎没动，与 7.8e-5 的权重变化一致。

### 结果层

| 模型 | 胜率 |
|---|---|
| OPD Student | 49/140 = 35.00% |
| 冻结 base（同批） | 51/140 = 36.43% |
| 冻结 base（9-21 旧测） | 45/140 = 32.14% |

配对：45 双赢、4 仅 OPD 赢、6 仅 base 赢、85 双输；McNemar p = 0.754。
同配置复测漂移 +6 局（+4.3 点），**与要检测的效应同量级**。

## 三、训练参数与算法审计

| # | 项目 | 结论 | 证据 | 级别 |
|---|---|---|---|---|
| A | 更新幅度 | LoRA rank16 + LR 1e-6 + 86 步 → 7.8e-5 相对变化；B 从 0 初始化，Adam 每坐标每步上界 ≈ LR，所以总量随步数线性增长 | `diagnose_adapter_scale.py` 实测；‖B‖ 最大 0.0117 | **阻断** |
| B | 目标函数形式 | 用的是 `k2 = 0.5·(s−t)²` 的单样本估计（`core_algos.kl_penalty`）。其梯度 ≈ ∇CE(π_S, π_T)（在自己采样的 token 上），而 CE = KL + H，**含熵最小化项**，因此会锐化而不是复现 teacher 分布；无显式正例（teacher 偏好的 token 不会被直接抬高） | loss 平 + 熵 −85% 同现；`log_prob_min_clamp` 只在 top-k 路径生效（`fsdp/losses.py:72`），本次未生效 | **严重** |
| C | heavy tail | 单 token 最大 k2 = 1046 ⇒ \|s−t\| ≈ 46（约 e^-46 的 teacher 概率），而均值 k2 ≈ 6.4；梯度被极少数 token 主导 | train.log 的 `loss_max` 分布 | 中 |
| D | mask 与教师对齐 | 逐项审计通过：mask = 动作跨度、教师行宽度与左移对齐、EOS 不入损失、特殊 token 拒绝；离线 192 项测试 + 真实 tokenizer 的布局验证脚本 | `verify_opd_layout.py`、`tests/` | 通过 |
| E | 采样温度 | 我们 rollout/训练温度 1.0；论文用 0.4。温度越高，单样本估计的尾部越重、采样 token 越偏离自身 argmax | 启动命令 vs R01 记录 | 中 |
| F | 提示词一致性 | 训练行与评测都使用冻结的 AgentBoard 提示词（训练首条 system 内容出现在评测 prompt json 中） | 逐字符串核对 | 通过 |
| G | 数据形态 | 训练状态来自**一次采集**的固定单步池（240 局、5524 回合）；论文是学生诱导的**多轮轨迹**在线训练。池子随训练变旧（off-policy 漂移），且单步无法表达多轮信用分配 | D01/D03 与 R01 | 中 |
| H | 评测功效 | 140 局；同配置复测漂移 ±6 局 | 本轮复测 | **阻断（对结论而言）** |

结论：**实现没有发现"错的"地方（对齐、掩码、提示词、温度一致性都过了），但有两处会让效果必然为零**：
更新幅度差 1–2 个数量级（A），以及目标函数只提供"这个采样 token 该压/该抬"的量级信息而不提供
teacher 的偏好分布或显式动作（B）。评测功效（H）使任何 ±3 点的结论都不可采信。

## 四、与其他论文对照：为什么我们的 OPD 没效果

| 维度 | SAGE-OPD（arXiv 2606.19659） | Agent-R1（我们审计过的 fork） | GKD / MiniLLM 类 | 我们的实现 |
|---|---|---|---|---|
| 监督单位 | 学生诱导的多轮轨迹 | 学生轨迹，teacher 的**动作**为监督目标 | 序列/分布 | 固定池里的**单个状态** |
| 目标形式 | 学生 token 上的蒸馏 + 选择性强干预 α=0.5、teacher 温度 0 | 序列级交叉熵（teacher 动作 = 显式正例） | top-k / 全分布 KL，reverse KL | 单采样 token 的 k2（无正例） |
| 归一化 | 全部 student token | — | — | 仅动作跨度 |
| 更新主体 | 论文未写 LoRA（verl 全异步标准配方通常为全参数） | 全参数 | 全参数 | **LoRA rank16** |
| LR / 步数 | 1e-6 / 1 epoch（与我们相同） | — | 通常 1e-5 级、数千步 | 1e-6 / 86 步 |
| 观测到的效果 | 1.7B：25.71 → 60.00（+34 点） | — | — | 49 vs 51（−2 局，p=0.75） |

三点解释，按贡献排序：

1. **更新幅度**：同样 LR 与 epoch，全参数训练每步让所有权重按 ~LR 移动（相对 ~5e-5/步），
   而 LoRA 的 B 从 0 开始、只有 rank16 的方向可用，实测只有 ~9e-7/步。
   论文那种 20–30 点级别的行为改变，需要 1e-3 以上的相对权重变化，我们差约 **100 倍**。
2. **目标函数缺少正例**：k2 在自身采样的 token 上只告诉模型"这个 token 概率该降/该升"，
   不告诉它"teacher 会选什么"；CE = KL + H 的分解又带来锐化效应（熵 −85% 已观测到）。
   论文用 teacher 温度 0 的决策与全 token 归一化，Agent-R1 直接用 teacher 动作当标签，
   都提供了显式正例。
3. **评测功效与协议差异**：140 局下的复测漂移（±4 点）大于我们要检测的效应；
   且论文的 ReAct/示范/停止符协议与我们的 AgentBoard 协议不同（R02/R03 已记录），
   跨论文的绝对数字本来就不可比。


## 四之二、更正与根因：老师被喂了学生的提示词渲染（2026-09-23 追加实测）

上一版把"没效果"主要归因于目标函数形式。追加实测后这个归因需要更正：**真正的问题是老师
看到的提示词不是它自己的模板渲染**，而 loss 的选择只决定了这个错误以什么形式表现出来。

实测证据（`scripts/measure_teacher_student_gap.py`，64 个真实学生动作、430 个受监督 token）：

| 观测 | 数值 |
|---|---|
| 学生模板是否含 thinking 分支 | **否**（`enable_thinking` 不在模板里） |
| 老师模板是否含 thinking 分支 | **是** |
| 用学生渲染的提示词时，老师在首个动作 token 的 argmax | `<think>`（64/64 回合） |
| 老师给学生那个 token 的 logprob | **−21.2 ~ −24.4**（学生自己是 ≈0） |
| 首个 token 的 gap 均值 / 中位 | **24.58 / 24.44** |
| 其余 token 的 gap 均值 / 中位 | 0.235 / ≈0 |
| 被 k3 的 clamp 吃掉梯度的 token 占比 | **16.5%**（其中首 token 占比 **100%**） |
| 用**老师自己的模板**渲染后，老师对同一 token 的 argmax / logprob | **`Action` / −0.0** |

独立交叉验证：让老师用自己的模板**直接贪心生成**动作，与学生记录的动作比较——
12 个状态里 **6 个不同**（如学生 `go to dresser 1` vs 老师 `go to coffeetable 1`）。
也就是说：**老师真正要纠正的位置恰好是动作行的第一个 token**，而那个位置在我们的渲染下
被替换成了 `<think>` 格式惩罚。

这条链把之前所有异常都解释通了：

* 训练损失平 + 熵掉 59%：每个回合只有首个 token 贡献真实梯度，方向是"压低动作标记的概率"
  （0.5 × 24.4² ≈ 298，而内容 token 的 gap≈0），既是错的方向，也只有 1 个 token。
* 09-20 烟测里 k3 出现"loss 非零、grad_norm=0"（台账 O23）：**正是这个 token** 的 k3 值被
  自己的 clamp 截到 10 → 梯度恰好为 0；内容 token 的 gap≈0 → 梯度也≈0，于是整体梯度为零。
* 为什么"老师 60% vs 学生 32%"没有体现在 token 监督里：老师的优势表现在**选哪个位置/顺序**
  （首 token 的决策），而不是在被学生强制前缀之后的内容 token 上。

因此顺序应当是：**先修渲染（老师用自己的 tokenizer + 模板，`enable_thinking=False` 会补出空
thinking 块），再重新量 gap 分布，最后才选 loss**。现有对齐代码本来就支持师生提示词宽度不同
（`remap_teacher_scores_to_student_layout` 用教师自己的 prompt 长度切片，O01/O03 就是为此写的），
所以修复本身是接线问题，不是重写。

修好渲染之后，可供选择的 loss 及其适用性：

| 选项 | 在修好渲染后的适用性 |
|---|---|
| k2（本次用的） | 可用，但仍是被单个采样 token 驱动的弱信号；建议配合 clamp 去尾 |
| k3（veRL 默认） | 修好后 clamp 不再打在信息 token 上，可重新评估；方差仍高 |
| `forward_kl_topk`（分布匹配） | **首选**：能表达"老师更想去哪里"，而不是只压当前 token；需要扩展教师接口返回 top-k |
| teacher 动作序列级监督（Agent-R1 风格） | 与"分歧集中在首个决策"这一实测结论最匹配，也最适合 greedy 评测 |

## 五、下一步（按性价比排序）

1. **方向性检查（最便宜）**：把已训 adapter 沿训练方向放大（B×k, k=10/30/100）做一次
   line search，在 20–40 局上看胜率与 invalid 率。若放大后明显变好 → 方向对、步长小，
   直接调 LR/步数；若变坏 → 目标函数方向有问题，先换目标再谈预算。
0. **（最高优先级，先做）修掉老师提示词渲染**：用老师自己的 tokenizer + 模板生成
   `teacher_prompt`（`enable_thinking=False` 补空 thinking 块），然后重跑
   `scripts/measure_teacher_student_gap.py`，确认首 token 的 gap 回到 ~0、
   信息量转移到内容 token；这一步没做之前，任何 loss 或预算调整都测不出东西。
2. **提高更新幅度**：LoRA LR 1e-4~1e-3（或改全参数 1e-6），步数 ×10；
   在这之前先用第 1 层的 `‖ΔW‖/‖W‖ ≥ 1e-3` 作为启动门槛。
3. **换目标**：top-k KL（veRL 已支持且会启用 clamp）或 teacher 动作监督（Agent-R1 风格），
   至少消掉 C 项的 heavy tail。
4. **扩评测**：valid_seen + valid_unseen（274 局）或每局多环境种子；并把
   "同配置复测漂移"作为常设噪声基线一起报告。
5. **数据形态**：从固定单步池迁到学生诱导的多轮轨迹（与论文一致），
   否则单步比较器的解释力有限（O08 已记录该边界）。
